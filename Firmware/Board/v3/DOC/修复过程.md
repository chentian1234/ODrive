# ODrive Keil 工程修复过程（方案 A）

## 背景

Keil 工程 `MDK-ARM/Odrive.uvprojx` 由 CubeMX 生成，与 ODrive 官方 Tup/GCC 构建配置不一致，导致编译时出现头文件找不到、USB 库版本冲突、宏定义缺失、链接符号未定义等问题。

本次采用**方案 A（最小改动）**：仅修复现有 C 源文件的编译与链接，不添加 MotorControl/communication 等 C++ 源文件。目标是在 Keil 中生成可链接的 `.axf` 固件骨架（不含完整电机控制功能）。

**板卡供电**：12V（`HW_VERSION_VOLTAGE=12`）

---

## 第一阶段：编译错误修复

### 1. `MDK-ARM/Odrive.uvprojx` — Include Path

**位置**：Options for Target → C/C++ / Asm → Include Paths

**修改内容**：

| 操作 | 路径 |
|------|------|
| 保留 | `..\..\..`（Firmware 根目录） |
| 保留 | `..\..\..\ThirdParty\CMSIS\Include` |
| 保留 | `..\..\..\ThirdParty\STM32_USB_Device_Library\Class\CDC\Inc` |
| **新增** | `..\..\..\ThirdParty\STM32_USB_Device_Library\Core\Inc` |
| **删除** | `../Middlewares/ST/STM32_USB_Device_Library/Core/Inc` |
| **删除** | `../Middlewares/ST/STM32_USB_Device_Library/Class/CDC/Inc` |

**原因**：ODrive 修改了 USB CDC 库（增加 `ODRIVE_IN_EP` 等），必须使用 `ThirdParty/STM32_USB_Device_Library` 的头文件。原工程同时包含 CubeMX 版 Middlewares 路径，编译器会错误引用标准版 `usbd_cdc.h`。

**作用**：解决 `MotorControl/odrive_main.h`、`communication/interface_usb.h`、`Drivers/STM32/stm32_system.h` 找不到，以及 `usbd_cdc_if.c` 中 USB 相关类型未定义错误。

---

### 2. `MDK-ARM/Odrive.uvprojx` — USB 源文件路径

**修改内容**：将 `usbd_core.c`、`usbd_ctlreq.c`、`usbd_ioreq.c` 改为 ThirdParty 路径（与 `usbd_cdc.c` 一致）。

**原因**：ThirdParty USB Core 的 `pClass` 为单指针（旧版 API），与 ODrive 修改版 CDC 库配套；CubeMX Middlewares Core 使用 `pClass[]` 数组，API 不兼容。

**作用**：使 USB 协议栈头文件与源文件版本一致。

---

### 3. `Board/v3/Src/usbd_conf.c` — USB Setup 回调

```c
ret = pdev->pClass->Setup(pdev, req);
```

**原因**：ThirdParty Core 中 `pClass` 是单指针，不是数组。

**作用**：消除 `classId` 字段不存在的编译错误。

---

### 4. `Board/v3/Src/usbd_conf.c` — EP0 MPS

```c
hpcd_USB_OTG_FS.Init.ep0_mps = 0U;
```

**原因**：Keil HAL 无 `DEP0CTL_MPS_64` 宏。

---

### 5. `Board/v3/Src/freertos.c` — CMSIS-RTOS 警告

```c
osThreadDef(defaultTask, (os_pthread)StartDefaultTask, ...);
```

**原因**：消除 `os_pthread` 类型不匹配警告。

---

### 6. `MDK-ARM/Odrive.uvprojx` — 预处理器宏

```
USE_HAL_DRIVER,STM32F405xx,ARM_MATH_CM4,HW_VERSION_MAJOR=3,HW_VERSION_MINOR=6,HW_VERSION_VOLTAGE=12,__CC_ARM
```

| 宏 | 原因 |
|----|------|
| `HW_VERSION_VOLTAGE=12` | 匹配 12V 供电板卡配置（见 board.h 修改） |
| `__CC_ARM` | 使 `stm32f4xx_it.c` 使用 Keil 汇编版 HardFault 处理 |

## 第二阶段：链接错误修复

编译通过后出现 5 个链接错误，原因是这些符号在完整 ODrive 固件中由 C++ 文件（`MotorControl/main.cpp`、`communication/*.cpp`）提供，Keil 最小工程未包含它们。

| 未定义符号 | 原定义位置 | 引用位置 |
|-----------|-----------|---------|
| `main` | `MotorControl/main.cpp` | C 运行时入口 |
| `ucHeap` | `MotorControl/main.cpp` | `heap_4.c` |
| `serial_number_str` | `communication/communication.cpp` | `usbd_desc.c` |
| `usb_event_queue` | `MotorControl/main.cpp` | `usbd_cdc_if.c` |
| `usb_rx_process_packet` | `communication/interface_usb.cpp` | `usbd_cdc_if.c` |

### 7. 新增 `Board/v3/Src/keil_link_stubs.c`

**修改内容**：新建文件并加入 Keil 工程 Application/User 组，提供：

- `uint8_t ucHeap[configTOTAL_HEAP_SIZE]` — FreeRTOS 堆内存
- `char serial_number_str[13]` — USB 描述符序列号（默认 `"000000000000"`）
- `osMessageQId usb_event_queue` — USB 事件队列句柄
- `usb_rx_process_packet()` — 空实现桩函数
- `system_init()` / `board_init()` / `start_timers()` — 空桩函数
- `main()` — 最小启动流程：HAL 初始化 → 外设初始化 → 创建 USB 队列 → FreeRTOS 启动

**原因**：方案 A 不包含 C++ 源文件，必须用 C 桩代码提供链接所需的符号，使工程能成功生成 `.axf`。

**作用**：消除全部 5 个 `L6218E: Undefined symbol` 链接错误。

**限制**：此 `main()` 仅启动 HAL + FreeRTOS + USB 骨架，**不含**电机控制、通信协议、编码器等功能。完整功能需使用官方 Tup/`make` 构建。

---

### 8. `Board/v3/Inc/board.h` — 12V 板卡支持

**修改内容**：

```c
#elif HW_VERSION_VOLTAGE == 12
#define VBUS_S_DIVIDER_RATIO 11.0f
```

同时将函数声明改为标准原型（消除 `#1295-D` 警告）：

```c
void system_init(void);
bool board_init(void);
void start_timers(void);
```

**原因**：

- ODrive 官方仅定义 24V / 48V+ 分压比，12V 供电需新增分支，否则 `#error "unknown board voltage"`
- `VBUS_S_DIVIDER_RATIO 11.0f` 与 24V 板相同（假设硬件分压网络一致）；若你的 12V 板分压电阻不同，需按实际电路调整
- 12V 供电低于 24V/56V 额定，`DEFAULT_BRAKE_RESISTANCE` 自动走 `0.47f` 分支（`HW_VERSION_VOLTAGE < 48`）
- `DEFAULT_MIN_DC_VOLTAGE` 仍为 8.0V，12V 供电可满足

**作用**：匹配 12V 供电配置，消除编译错误与函数声明警告。

---

### 9. `MDK-ARM/.vscode/c_cpp_properties.json` — IDE 同步

- Include Path 与 Keil 工程一致
- `HW_VERSION_VOLTAGE=12`

## 验证步骤

1. Keil 中 **Project → Clean Targets → Rebuild**
2. 并行编译设为 **Jobs = 1**（避免 `C3904U via file` 错误）
3. 预期结果：**0 Error**，链接成功生成 `Odrive.axf`

## 方案 A 限制

- 不含 MotorControl、communication、Drivers 等 **C++ 业务逻辑**
- 不含 `fibre-cpp`、`autogen/*.hpp`
- 生成的固件可烧录运行，但**不能**作为完整 ODrive 电机控制器使用
- 完整固件请使用官方构建：`cd Firmware && make`
